# Galaxy Agent Chat — Frontend

Next.js App Router UI on **port 3000**. Product chrome is branded **Magica** (“Your AI worker”). The app talks only to the backend **`/api`** surface with a Clerk session JWT. It does not call Magica or OpenRouter directly.

Backend docs: [`../backend/README.md`](../backend/README.md).

## Stack

| Piece | Role |
| --- | --- |
| Next.js 16 + React 19 | App Router pages |
| Clerk | Sign-in / sign-up / session token |
| TanStack Query | Server state (`chats`, `messages`, `runs`, `credits`, settings) |
| Zustand | Sidebar, composer draft, optimistic outgoing |
| Trigger.dev React hooks | Live `thinking` / `assistant` streams |
| Uppy + Transloadit | Composer attachments |
| Tailwind 4 + shadcn/ui | Light-first Magica palette (accent `#6D5EF7`) |
| next-themes | System / light / dark |
| Sonner | Toasts |

## Local setup

From the **monorepo root** (preferred):

```bash
cp frontend/.env.example frontend/.env.local
# same Clerk app as the backend
pnpm install
pnpm --filter backend contracts:export   # writes src/generated/api.ts
pnpm dev                                 # frontend :3000 + backend :3001
pnpm dev:trigger                         # required for live runs in trigger mode
```

From this directory only (backend must already be running on :3001):

```bash
pnpm dev
pnpm test
pnpm test:e2e
pnpm typecheck
```

Open [http://localhost:3000](http://localhost:3000). Without `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` the shell shows **Add Clerk keys to start**.

## Environment

Copy [`.env.example`](./.env.example) to **`.env.local`** (not `.env`).

| Variable | Required | Purpose |
| --- | --- | --- |
| `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` | yes | Clerk browser SDK |
| `CLERK_SECRET_KEY` | yes | Clerk middleware `auth.protect()` |
| `NEXT_PUBLIC_CLERK_SIGN_IN_URL` | no | Default `/sign-in` |
| `NEXT_PUBLIC_CLERK_SIGN_UP_URL` | no | Default `/sign-up` |
| `NEXT_PUBLIC_API_URL` | yes | Backend origin (`http://localhost:3001`) |

Both Clerk keys must be set or middleware is a no-op pass-through. Use the **same Clerk application** as the backend.

Never commit `.env.local`.

## Architecture

```
Clerk session
    → apiFetch(NEXT_PUBLIC_API_URL + /api/...)
        → TanStack Query hooks
            → ChatWorkspace
                → Sidebar / TopBar / Composer / MessageList
                → useRun (Trigger streams + poll overlay)
```

- Typed DTOs and `LIMITS` come from `src/generated/api.ts`.
- That file is generated by `pnpm --filter backend contracts:export`. **Do not edit it by hand.**
- `src/lib/api/client.ts` attaches `Authorization: Bearer <Clerk JWT>` via a token getter set in `src/components/providers.tsx`.

| Module | Backend paths |
| --- | --- |
| `lib/api/chats.ts` | `/api/chats` |
| `lib/api/messages.ts` | `/api/chats/:id/messages`, `/api/chats/:id/turns` |
| `lib/api/runs.ts` | `/api/runs/:id`, stop, realtime-token, waitpoint resume |
| `lib/api/credits.ts` | `/api/me/credits` |
| `lib/api/uploads.ts` | `/api/uploads/*` |
| `lib/api/settings.ts` | `/api/me/api-keys`, `/api/me/webhooks` |

The browser never calls `/v1`. Settings explains that public integrations use `Authorization: Bearer gx_live_…` against the backend `/v1` routes.

## Chat UX

### Sidebar

Magica wordmark, search, **New task** (`/`), recent chats, account menu (credits, grant line, theme). Several rail items (Projects, Library, Tools, …) toast “Not available in this workspace.”

### Composer

- Draft stored in Zustand (`composerDraft`).
- Enter sends; Shift+Enter newline; Shift+Tab toggles **Plan**.
- Attachments via Uppy → signed Transloadit assembly → `POST /api/uploads/complete`. Max **0.5 GiB** / file; `image/*`, `video/*`, `audio/*`. Pending rows use id prefix `pending:` until complete.
- Send is disabled while uploads are pending or a run is active.
- While a run is `queued` / `thinking` / `working` / `waiting` / `stopping`, the send control becomes **Stop** (`POST /api/runs/:id/stop`).
- Every turn sends `model: "openrouter/free"`, a new `clientIdempotencyKey`, optional `attachmentIds`, and `planMode`.

One active run per chat is enforced by the backend (`409 ACTIVE_RUN`). The UI toasts the error and restores the draft. There is no “retry this run” button — failed turns say **Send a new message to continue.**

### Messages and work

`MessageList` merges persisted messages with the live run. Assistant turns show thinking, a **Working** timeline (Magica tool steps + M credits), generated media, and a usage footer.

### Waitpoints

| Kind | UI |
| --- | --- |
| `questions` | `QuestionDock` replaces the composer |
| `plan` / `options` / `media` / others | `WaitpointOverlay` modal (Approve / Reject) |

Resume needs a real `token` and `resumeKey` from the run payload. Timeline-only question stubs cannot resume until the waitpoint is loaded.

### Top bar

“Magica Auto” (display only — model is always OpenRouter Free), Files (unavailable toast), and the credit balance.

## Credits display

Wallet integers are Magica micro-units.

- Chrome (`TopBar`, account menu): `formatCredits` → `9.80M` (`src/lib/format-credits.ts`).
- Tool / usage copy: `formatMagicaCredits` → `0.32M credits` (`src/lib/format-magica-credits.ts`).
- New-user grant copy uses `LIMITS.initialGrant` (`10_000_000` → **10.00M**).

`useCredits` reads `GET /api/me/credits` with `staleTime: 0` and an 8s refetch. Workspace also invalidates `["credits"]` when a run becomes terminal, so Magica burns and token charges show up without a full reload.

## Realtime

`src/hooks/use-run.ts`:

1. Poll `GET /api/runs/:runId` (800ms while active if Trigger is not connected; 2.5s on error).
2. If the turn response (or a token refresh) includes Trigger access, subscribe with `useRealtimeRun` + `useRealtimeStream` for `thinking` and `assistant`.
3. `overlay-run.ts` merges stream text onto persisted blocks. Terminal status on the polled run always wins.

If Trigger is down, the UI keeps working from Postgres polls. Opening `/c/:chatId` with `chat.activeRunId` reattaches to in-flight work.

Query keys: `["chats"]`, `["chats", chatId]`, `["chats", chatId, "messages"]`, `["runs", runId]`, `["credits"]`, `["api-keys"]`, `["webhooks"]`.

## Settings

`/settings` (same sidebar + top bar):

- **API keys** — create (secret shown once), list, revoke. Use the secret as `Bearer` on `/v1`.
- **Webhooks** — URL + signing secret (shown once), delete.

Copy on the page: MCP is not part of this app.

## Theme

`next-themes` default **light**, system supported. Sidebar account menu switches system / light / dark. Stop button uses `#ff3b30`. Magica mark is `src/components/chat/magica-mark.tsx`.

## Product constraints the UI assumes

- Model is always `openrouter/free`.
- Composer stays locked for the whole active run, including `waiting` and `stopping`.
- Failed or cancelled history is display-only; continue with a new user message.
- Attach needs backend Transloadit keys; text chat works without them.
- Durable Magica work needs the backend Trigger worker (`pnpm dev:trigger`).
